    tssa.footprint: vehicle ground footprint from tracked boxes (VehFootPrinter)¶

    Date: 2026-11-10 Status: approved by the user, 2026-11-10 (rev 4.1); rev 4.2 is an implementation note (§4.3). §19 adds the validation results (2026-11-11).     1. Intent¶

    The study compared seven ways to get a vehicle's ground position and footprint from a DNT bbox, through one shared segmentation and smoother. This design moves all seven into tssa, so a later project (PET, conflicts, speed) can get vehicle footprints from tracked boxes and video without the study's scripts, and can still compare methods.

    tssa already has the steps around it: - tssa.transform.DistortedHomography: image ↔ ground; - tssa.smooth.TrackSmoother: segments and smooths ground positions; - tssa.speed.SpeedCalculator: speed from smoothed positions.

    None of them knows where on the vehicle its input point is. Today a user projects the bbox bottom-centre (the study's M1) and smooths that. The study showed this point is the worst choice for PET: it sits 4.5 ft from the consensus of the independent cues, its bias depends on direction (left turns +3.8 ft ahead), it shifts PET by up to 0.43 s (p90; 0.75 s on right turns), and it reads trap speeds 0.9 mph lower than M6.

    VehFootPrinter supplies the missing step: video + pixel boxes → a ground reference point at the body centre, with its covariance (before smoothing) → an oriented polygon of the right size (after smoothing).

    1.1 The seven methods¶

    Name Study method Needs Native output Study result
    M1 bbox bottom-centre homography point (foot of the box, not the body centre) 4.59 ft from M6; PET shift p90 0.43 s
    M2 M1 moved half a nominal width away from the camera homography point 1.65 ft from M6; |Δ speed| 0.40 mph; no inference
    M3 nominal rectangle at the reference heading, fitted to the bbox homography, ψ_ref rectangle, orientation imposed trucks 1.4 ft from M6 (M2: 6.7 ft)
    M4 CarFusion wheel keypoints keypoints, camera, ψ_ref point + directed heading 6.1% coverage; 1.18 ft from M6
    M5 SAM lower outline, nominal rectangle fit masks rectangle + axis 58.7% coverage; e2e jitter doubles
    M6 UrbanOmniDetect-2 cuboid bottom face cuboids measured quadrilateral + axis 99.5% coverage; recommended for PET and speed
    M7 wheel-anchored rigid-body fit per segment (buses, trucks) masks, camera, M2, ψ_ref centre + directed heading + fitted L, W, covariance 19 of 25 display solves pass (run 20261110_161113_s0); the user reviewed the M7 clips on 2026-11-10

    The default chains (§7.8) follow the study's recommendation (M6 for cars) and its combined PET product (M7 for buses and trucks, M6 next, then the class fallback).

    2. Goals, non-goals, anti-goals¶

    Goals - One public class, VehFootPrinter, with a frozen FootprintConfig, in the style of TrackSmoother / SmoothConfig. - All seven methods as registered locators (§7), usable alone, in per-class fallback chains, or side by side (compare()). - Per row: reference point, 2 × 2 position covariance, the locator that supplied it, why the others failed, native orientation and size. - After smoothing, per row: footprint orientation, motion heading, length and width in feet with their source, four corners; optionally shapely polygons. - Detector wrappers and matching (§6), so tssa can go from video to footprints. - A pinhole camera fitted to a ground homography (§8), needed by M4 and M7. - The study's synthetic tests ported under tests/, and one validation run that reproduces the study's NW-clip results (§14).

    Non-goals (this round) - The study's evaluation machinery: the three products (metric-native, metric end-to-end, display), eligibility and analysis-zone rules for metrics, plausibility table, stop mask, review clips, pinned-input hashing, sample-independence checks, camera-sensitivity reports. compare() gives a project what it needs to build its own. - M7's metric solves per eligible run. tssa has one product, so M7 solves once per segment, the study's display solve. - Manual footprint keyframes (the user decided not to annotate, 2026-11-08). - Training models, shipping weights, real-time processing, PET itself.

    Anti-goals (failure even if it "works") - A method looks better because it was smoothed differently. Every locator goes through the same segmentation and smoother, with the same noise model (§7.9). The only exception is M7's admitted pseudo-measurements, which carry M7's own covariance and are marked (§7.7). - Imposed sizes reported as measured. dims_source says whether a size was measured, partly prior, or nominal (M7: by information, M7 design §8.3). - Silent drops or invented support. Every input row comes back once. A row without a reference point says which locators were tried and why each failed. An M7 row with no observation of its own is never native. - Heavy imports for light use. Without torch, ultralytics or OpenCV installed, these must work: import tssa; loading a saved HomographyTransform or DistortedHomography (load_json, load_matrix) and projecting with it; fitting the pinhole camera; and M1, M2, M3, M4 and M6. OpenCV is still needed to fit a new homography, and for M5 and M7, which rasterise mask contours. torch and ultralytics load only when a detector runs (§6, §8, §13). - Study constants or machine paths in the code. NW-clip values are defaults with a cited source; checkpoints and repository paths are arguments. - Silent drift from the study. Every deliberate change is listed in §15.

    3. Where it sits in the pipeline¶

    video ─► detect.run(...)            keypoints, cuboids, masks    (optional; §6; or bring your own tables)
                 │
tracks ──────────┼─► VehFootPrinter.locate()
                 │      1. project M1, build ONE segment grid  (TrackSmoother.segment, §5.2, §9)
                 │      2. M2 everywhere, reference pass: smooth M2 → ψ_ref        (§9)
                 │      3. per class, run its chain of locators on the grid        (§7)
                 │         → seg, fp_x, fp_y, fp_cov_*, fp_source, native orientation and size
                 ▼
            TrackSmoother.smooth(segmented=True)  same grid, covariance columns  (§5)
                 ▼
            SpeedCalculator.calculate()
                 ▼
            VehFootPrinter.polygons()  orientation, size, corners               (§10)

    estimate() runs locate → smooth → speed → polygons with vehicle defaults (§11.3). locate() and polygons() stay public for users who want their own smoother or speed settings. compare() runs several methods on the same grid (§11.2).

    The order follows base design §8.1: segmentation is built once, before any method; reference points are fixed before smoothing; orientation and polygon come after, from the smoothed motion.

    4. Inputs¶

    4.1 Tracks¶

    A DataFrame, one row per (track, frame); column names configurable (§12):

    Column Meaning
    frame integer frame number, zero-based, the video's frame index
    track track id
    x, y, w, h bbox top-left and size in distorted image pixels
    cls class id per row (DNT: 2 car, 5 bus, 7 truck). The class used is the track's majority class, cls_track.
    interp (optional) 0 detected, 1 filled upstream

    All tracks of a frame should be passed, including tracks the user does not want footprints for. M7 drops outline columns that a nearer box covers, and detector matching is one-to-one over every box of a frame (run report R21). locate(..., only_tracks=[...]) limits the output without hiding the other boxes.

    4.2 Homography and the ground-model adapter¶

    VehFootPrinter wraps whatever it is given in tssa.transform.ground.GroundModel (new):

    GroundModel.wrap(homography, image_size=None) -> GroundModel
    image_to_world(uv) / world_to_image(EN)   # distorted pixels <-> world metres
    undistort(uv) / distort(uv_u)             # identity when the homography has no distortion model
    world_to_undistorted(EN)                  # direct through the inner undistorted-image homography when there is one
    image_size                                # (width, height) px
    • Distortion.
    • For DistortedHomography, undistort and distort are its own, and world_to_undistorted uses its inner homography directly. The round trip through distort() would add the iteration error of its 20-step inverse.
    • For HomographyTransform, or any object with only image_to_world / world_to_image, both are the identity and world_to_undistorted = world_to_image.
    • An object that has one of undistort / distort but not the other is rejected.
    • Image size. Taken from the explicit image_size argument (VehFootPrinter(..., image_size=(640, 480))), else from the homography's image_size attribute (DistortedHomography has one). If the two disagree, ValueError. If neither exists, construction fails with ValueError: the edge flag (§7.10) and the camera's principal-point prior (§8) both need it.
    • Pixel spaces. The camera works only in undistorted pixels. Its fit targets are world_to_undistorted of the zone grid, and its consistency check compares distort(camera.project(X, z = 0)) with world_to_image(X), as base design §5 specifies. M4 hub points and M7 tyre candidates are undistorted before they meet the camera (M7 design §5).

    4.3 Detection tables¶

    Written by tssa.footprint.detect (§6), or by the user's own pipeline in the same format. All pixels are distorted image pixels, keyed by (track, frame) after matching.

    Table Columns Used by
    keypoints track, frame, iou, u0, v0 … u3, v3 (CarFusion wheels 0 RF, 1 LF, 2 RB, 3 LB) M4, M7 (optional cue)
    cuboids track, frame, iou, gu0, gv0 … gu3, gv3 (bottom-face corners, any start, any winding) M6
    masks MaskTable: (track, frame) → list of contour polygons (k, 2) of every mask component, largest first, plus .outlines: the lower outline taken from the raw mask at segmentation time M5 (the stored outline, else one rebuilt from the contours), M7 (components with at least 5% of the area)

    One SAM pass serves both M5 and M7 (the study ran SAM twice, §15): - M5 reads the lower outline that MaskSegmenter takes from the raw mask, exactly the study's M5 input. Without one (masks from elsewhere), it rebuilds the outline from the contours. - M7 keeps the components holding at least M7_MIN_COMPONENT_FRAC (5%) of the summed area + perimeter, the rule the study applied when it wrote its SAM cache. Applied to an already filtered table it keeps every component, so the study's cache works as is.

    rev 4.2 (implementation, 2026-11-10): rev 4.1 stored only the 5% components and rebuilt M5's outline from them. The validation run measured the cost: outlines identical to the study's on 3,769 of 4,129 bus and truck rows, and M5 validity changed on 62 of them (§19).

    4.4 Camera zone¶

    M4 and M7 need the pinhole camera of §8, which is fitted over a ground region. zone: a shapely polygon in world metres. Helper: zone_from_points(world_points, buffer_ft=15) (base design §7: GCP convex hull + 15 ft). Without a zone, camera-dependent locators fail with camera_invalid.

    5. Changes to tssa.smooth (the answer to Q4)¶

    Recommendation. Use the study's full measurement covariance, not a scalar σ. Two reasons: - The ground scale of a pixel is strongly directional in this view: the largest-to-smallest ratio has median 3.3 and p95 5.0 (base design §9). A scalar σ under-smooths along the camera ray and over-smooths across it. - M7's display pseudo-measurements carry their own 2 × 2 covariance (M7 design §9.3). A per-row covariance column carries them with no special path, replacing the study's R_override.

    All additions below are backward compatible: calls that use none of the new arguments give identical results, and the existing smooth and speed tests must pass unchanged.

    5.1 Per-row covariance¶

    SmoothConfig.cov_cols: tuple[str, str, str] | None = None: names of per-row covariance columns (xx, xy, yy) in m². Three columns make R symmetric by construction. - The rts kind uses them as the measurement covariance R on measured rows where all three are finite; otherwise sigma_col; otherwise the method's sigma. - A supplied covariance is final. fill_scale is applied only to noise that comes from sigma_col or the method's sigma, never to cov_cols. Whoever writes the covariance applies any inflation. For VehFootPrinter that rule is §7.9. - A measured row whose covariance is not positive definite (xx > 0, yy > 0, xx·yy − xy² > 0) raises ValueError. - Kinds without a noise model (ma, sg) ignore it, as they ignore sigma_col today.

    5.2 Segmenting once, smoothing many times¶

    TrackSmoother.segment(tracks, ref_tracks=None, allow_missing=False) -> DataFrame

    The public form of today's _grid. It returns the structural table only: track, frame, seg, seg_len, interp, fill_reason, gap_id, one row per input row plus the inserted rows (interp = 2). No positions are returned, so none can be reused by mistake.

    With allow_missing=True, rows with a non-finite position are accepted and kept: - Jump detection and gap classification use only the finite rows. A run of missing rows between two finite rows counts as part of the gap between them. - Interior run, gap filled (short enough, plausible implied speed, no jump): the missing rows stay in the segment with their own interp (0 or 1) and fill_reason = "no_position". Frames with no row at all are inserted as today (interp = 2). - Interior run, gap not filled: the track is split there, and the missing rows get seg = −1, fill_reason = "no_position". - Prefix, suffix, or whole track (missing rows before a track's first finite row, after its last, or on a track with no finite row): seg = −1, fill_reason = "no_position". They are never extrapolated.

    Without allow_missing, a non-finite position raises, as today.

    TrackSmoother.smooth(tracks, ref_tracks=None, segmented=False)

    With segmented=True, the input already carries the structural columns seg, interp, fill_reason (from segment() or from VehFootPrinter.locate()). Then: - No re-segmentation. The input is validated: no repeated (track, frame), and every (track, seg ≥ 0) has consecutive frames; otherwise ValueError. seg_len is recomputed. seg, interp and fill_reason are input columns in this mode, so they pass through unchanged and are not clashes. The smoother adds only <pos>_smooth and fallback (or the compare() columns). - Measurement admission follows the positions, not interp. A row is a measurement exactly when it has seg ≥ 0 and both position values are finite. interp is provenance only. It selects fill_scale for σ-based noise on interp = 1 rows, and it no longer clears observations. A finite position on an interp = 2 row (an M7 pseudo-measurement on an inserted frame, §7.7) is measured. - Nothing from the segmentation pass is reused. Observations come only from this call's position columns. Kinds that need a value on every row (ma, sg, and the short-segment fallback) get this call's measurements linearly interpolated across unmeasured rows of the segment, and held constant before the first and after the last measurement. - Coordinates. The local origin is computed from this call's finite positions (floor of the minimum, as today), and the output is returned in input coordinates, rounded to three decimals like every added numeric column today. - Segments without enough measurements: - 0 measured rows: NaN positions, fallback = 1; - 1 measured row: that position on that row, NaN elsewhere, fallback = 1; - fewer than the method's minimum otherwise: the interpolated raw positions, fallback = 1, as today. - seg = −1 rows are returned with NaN positions and fallback = 1.

    Without segmented, behaviour is unchanged.

    This is how one segmentation serves every method, as the study required (base design §7, anti-goal 1), without any method seeing another's positions.

    5.3 rts_smooth fixes¶

    tssa.smooth.methods.rts_smooth needs two fixes, both found by the review: - Guard. Fewer than 2 measured rows raises ValueError with a clear message, not IndexError. Every caller checks first (§5.2, §10.2). - Start time. The forward pass starts at the first measured row i0, from the state of rows i0, i1 as today. Rows before i0 take the smoothed state at i0, extrapolated backward at its constant velocity: x_k = x̂_{i0} − (i0 − k)·dt·v̂_{i0}. Today the filter starts at row 0 with the state of row i0. On exact constant-velocity data with a 10-frame missing prefix, that gives 1.54 m at frame 0 where the truth is 0. - Existing callers are unaffected: today every segment starts with a measured row (inserted rows lie only between observations), so i0 = 0.

    6. Detectors (tssa.footprint.detect, optional install)¶

    6.1 Packaging¶

    • Extra: pip install tssa[detect] adds torch, ultralytics, opencv-python, huggingface_hub. requirements.txt already lists OpenCV.
    • Every import of these is lazy, inside the function that needs it. A missing package raises ImportError naming the extra.
    • UrbanOmniDetect-2 is not pip-installable. CuboidDetector(weights, repo_root) puts repo_root first on sys.path and imports v2.hybrid_v2 before loading, as the study's infer.load_uod does.
    • No weights ship with tssa. The keypoint model downloads from Hugging Face at a pinned revision (default: the study's 48b5795f3b79cdfe7ff6588812aa388a6a7fdd9d of kiselyovd/vehicle-keypoints, weights.pt). An unpinned revision raises.

    6.2 Classes¶

    Class Model Output table Study defaults
    KeypointDetector(repo, filename, revision, conf=0.08, imgsz=640) CarFusion YOLO pose keypoints infer.run_keypoints
    CuboidDetector(weights, repo_root, conf=0.08, imgsz=640, prefer_cls=(2, 5, 7)) UrbanOmniDetect-2 cuboids infer.run_uod
    MaskSegmenter(weights, min_component_frac=0.0) SAM2.1, box-prompted with each track bbox masks infer.run_sam_full

    Full-frame inference for keypoints and cuboids; SAM is prompted with the requested rows' boxes (all of a frame in one call). Masks are > 0.5, resized to the frame if needed, and stored as external contours (CHAIN_APPROX_NONE) of every component (by default), largest first, together with the row's lower outline from the raw mask.

    6.3 Matching¶

    match_frame(track_xyxy, det_xyxy, min_iou=0.3, det_cls=None, prefer=None): one-to-one assignment of detections to every track box of the frame, maximising total IoU (scipy.optimize.linear_sum_assignment), edges below min_iou removed, preferred classes first (run report R21). It needs only numpy and scipy, so it lives in the core package (footprint/match.py) for users with their own detectors.

    6.4 Runner and cache¶

    tables = detect.run(video, tracks, detectors=[KeypointDetector(), CuboidDetector(w, root), MaskSegmenter(w)],
                    rows=None, cache_dir=None)          # -> {"keypoints": df, "cuboids": df, "masks": MaskTable}
    - Frames are read once, sequentially (cv2.VideoCapture), and every detector runs on each frame read. - Two separate inputs. - tracks is the matching context: every box of every frame. It is always used whole, for the one-to-one matching of §6.3, however few rows are requested. - rows selects the output (and cached) rows. - rows default, independent of any configuration: every row of tracks, for every detector. The runner knows nothing about chains. - To infer only what a configuration needs, ask the printer: vfp.required_rows(tracks) -> {"keypoints": df, "cuboids": df, "masks": df}. It returns, per table, the rows of tracks whose class chain contains a locator that needs that table (a custom car chain with M5 makes car rows appear under masks). Pass the result as rows=, either as one dict or per detector. - Cache (base design §10), optional: cache_dir/<detector>/<key>/, where key hashes the video file, the full track table (the matching context), the weights (file SHA-256 or HF revision), the detector parameters and a per-detector CODE_VERSION. A changed setting gives a new key, never silent reuse. A run infers only rows the cache lacks, and saves every 200 frames. MaskTable is stored as npz. The study's lesson applies: arrays are read once per load, not per row (run report, "Performance fix").

    7. Locators (before smoothing)¶

    7.1 Contract¶

    @register_locator("M5", needs=("masks",), scope="row", point_only=False)
def locate_m5(rows: pd.DataFrame, ctx: LocateContext) -> LocatorResult: ...

    7.6 M7 (wheel-anchored rigid fit), scope="segment"¶

    Ported from m7.py, m7_candidates.py, and the job and table parts of m7_runner.py, in the state of 2026-11-10 (run 20261110_161113_s0). This is the M7 design rev 7 plus the M7 notes' later decisions: - front rule travel (2026-11-09); - width held at the class prior when the silhouette resolves width coarser than the threshold (2026-11-10). The study code is authoritative (m7.py: w_held = M7_W_HOLD_FT_PER_PX is not None and w_ft_per_px > M7_W_HOLD_FT_PER_PX): - w_ft_per_px is the width change per pixel of far-end silhouette, median over frames (width_resolution). Larger means coarser. - Held when w_ft_per_px > 0.3, a strict inequality: exactly 0.3 is not held. - w_ft_per_px = inf (no frame's extreme column moves with W) is held. - w_hold_ft_per_px = None never holds. - a width on its bound does not fail the solve (M7_W_BOUND_FAILS = False); - fitted tyre inset; - tyre lowest-point model; - image-edge σ; - pair-wheelbase restarts; - 30 outer rounds; - tandem and far-side targets off.

    All M7_* settings move into FootprintConfig.m7 (§12.2) with these values.

    Per segment of a cls 5/7 track (m7_classes): 1. Frozen observations: frame_obs_from_mask on every row with a mask. Other boxes of the same frame come from the full track table (§4.1). 2. Initial pose (study m7_runner._init_pose, then m7.initial_x): - centre: the M2 points (§9), linearly interpolated across rows without one; - heading: ψ_ref interpolated as a unit vector, or the path direction where ψ_ref is missing. 3. Fit: solve_track. Segments shorter than min_support_frames (10) fail with too_few_frames. 4. Rows: - wheels2 / wheel_front / wheel_rear / silhouette rows are native; - kinematic rows are ok = False, fail_reason = no_observation, and their pose is kept in m7_x, m7_y, m7_psi_deg; - a failed solve fails every row with its gate reason (param_bound, wheel_resid, articulated_suspect, …).

    Extras: the M7 design §9.4 columns with the m7_ prefix (support, own pose, per-solve parameters, size sources, uncertainty, flags), plus m7_w_held.

    7.7 M7 pseudo-measurements¶

    M7 design §9.3, user decision Q2, adapted to the one-product world. - Admission (the study's predicate, products._product): a row becomes a measurement when - its segment's M7 solve passed, - m7_support = kinematic, and - its M7 pose and m7_cov_centre are finite.

    Nothing about the box is checked. Admission does not look at the projection gate (§7.10), the box fields or the Jacobian, so it applies to all three row kinds of §7.10 that lie in a segment (seg ≥ 0): - inserted frames (interp = 2): no box at all; - original rows whose projection was rejected: inside a segment, fill_reason = "no_position". Admission overrides the rejection, as in the study, where the display gate was proj_valid and admission ignored it. The M7 pose comes from the camera and motion model, not from the bbox bottom. - original rows with a valid projection.

    Never admitted: rows with seg = −1, which belong to no segment and no solve. The smoother measures any segment row with a finite position (§5.2), so an admitted point is used, not cleared. - No box-derived values on admitted rows. Their fp_x, fp_y is the M7 pose and their covariance is the one below. fp_sigma is computed from it; no box, Jacobian or fill_meas_scale enters. - Native M7 rows are gated like any box row, also as in the study (nat_ok = native_valid & gate): a wheels2 / wheel_* / silhouette row whose projection was rejected is not used as a native measurement. It is not admitted either, because admission requires kinematic support, so the next locator in the chain tries it. - Covariance: R = kin_meas_scale² · m7_cov_centre + (kin_sd_floor_ft · 0.3048)² · I (defaults 2.0 and 0.5 ft). It is final (§5.1), so no interp-based inflation is added, whatever the row's interp. - Marking: fp_source = "M7", fp_support = "kinematic". - Precedence: M7 native rows, then admitted rows, then the next locator in the chain. - admit_kinematic=False turns it off, giving the study's metric behaviour (no pseudo-measurements).

    7.9 Shared noise model¶

    For every locator except M7's admitted rows, the measurement covariance is the study's (smoothlib.methods.measurement_cov): 

    R = (sigma_k · h)² · J Jᵀ      J = 1-px Jacobian of image_to_world at the bbox bottom-centre, h = box height
    sigma_k = 0.03 (study RTS_SIGMA_K). It comes from the box, not from the locator, so no locator looks steadier because it was given a smaller σ. It is written as fp_cov_xx, fp_cov_xy, fp_cov_yy, plus fp_sigma = sqrt(trace(R) / 2) for smoothers that take a scalar.

    Scaling by support type. Supplied covariances are final (§5.1), so locate() applies every inflation itself:

    Row Covariance
    box-based locator (M1–M7 native) on an original row with a valid projection, interp = 0 R as above
    box-based locator, interp = 1 (box filled upstream) fill_meas_scale² · R, fill_meas_scale = 4.0 (study FILL_MEAS_SCALE, applied as in the study's smooth_series)
    M7 admitted pseudo-measurement, any interp §7.7, no further scaling
    no reference point NaN; the row is not measured

    fp_sigma is computed from the scaled R. A smoother given sigma_col="fp_sigma" instead of the covariance columns would apply its own fill_scale on top, so estimate() always passes the covariance columns (§11.3).

    8. Pinhole camera (tssa.transform.camera)¶

    Ported from the study's camera.py (base design §5). It is a transform, so it goes into tssa.transform next to the homography. - PinholeCamera: project(XYZ) (world 3-D → undistorted px) and ray(uv). - PinholeCamera.fit(homography, zone, f_fixed=None, free_principal=True, pp_prior=1e-3): least-squares fit of f, (cx, cy), R and C to a 1 m grid over the zone, mapped with the homography. A weak prior pulls (cx, cy) toward the image centre, which picks one exact camera out of the family (R18). - consistency(cam, homography, zone): RMS and max ground-projection residual; ok at RMS ≤ 1 px and max ≤ 3 px. - sensitivity(...): refits at f × 0.87 / 1.0 / 1.13. - hub_to_contact(cam, uv, r_m): the ray meets z = r, then drops vertically.

    • Pixel space and image size come from the GroundModel adapter (§4.2):
    • fit targets: world_to_undistorted of the zone grid;
    • consistency check: distort(project(X, z = 0)) against world_to_image(X);
    • principal-point prior: toward the centre of image_size.

    fit takes a GroundModel; a plain homography is wrapped, and fails without an image size. - No OpenCV. - cv2.Rodrigues becomes scipy.spatial.transform.Rotation.from_rotvec / as_rotvec. - The initial plane homography (cv2.findHomography(…, 0), plain least squares) becomes a normalised DLT in numpy. - The ported test_camera checks parity, and so does the NW-clip camera of §14.3 (f = 319.55 px, (cx, cy) = (334.10, 240.13), height 6.73 m, within 0.01 px / 0.001 m).

    VehFootPrinter fits the camera lazily, the first time a locator needs it. A failed consistency check makes M4 and M7 fail with camera_invalid (base design §6.1; M7 design §7.5). The fit and its residuals go into VehFootPrinter.info (§11.4).

    9. Grid, M2 pass and reference heading¶

    Inside locate(), before any chain runs: 1. M1 points for every row. Rows that fail the projection gate (§7.10) get NaN, not a point. 2. Grid: smoother.segment(m1, allow_missing=True) (§5.2). Every method uses this grid. Rows with an invalid projection keep their identity: - one invalid row (or a short run) between valid observations: it stays in the segment, unmeasured, fill_reason = "no_position"; - a run too long to bridge: the track splits there, and the run gets seg = −1; - an invalid prefix or suffix, or a track with no valid projection at all: seg = −1.

    In every case these are box_rejected rows (§7.10): fp_fail starts with projection, and no box-derived ground point is invented for them. A box_rejected row inside a segment can still receive an admitted M7 pose (§7.7), and then fp_source = "M7" and fp_support = "kinematic". Otherwise fp_source = "none". seg = −1 rows are never admitted, and reach every later step with NaN outputs. 3. M2 points for every row with a valid projection. 4. Reference pass: smooth M2 on the grid (segmented=True), compute velocities, and apply the motion-heading rules (§10.1) to get ref_heading_deg. It is needed by M3, M4 (pair acceptance, front) and M7 (initial heading), and stored for M5/M6 axis direction.

    Dropped from the study: the approach-direction fallback for tracks that never move (it needs movement labels, which tssa inputs do not carry). Those rows get NaN ψ_ref; M3 and M4 fail with no_heading; M7 starts from the path direction, as m7_runner._init_pose already does.

    Segmentation basis. The study split on pixel jumps (0.5 box heights per frame, SPLIT_SPEED, SPLIT_LOGH). TrackSmoother splits on ground speed. The vehicle defaults in §11.3 use ground speed. The validation run (§14) counts segments against the study's grid and reports the difference. A pixel-jump rule in tssa.smooth is a follow-up, not part of this round.

    10. Orientation and polygons (after smoothing)¶

    polygons(table) takes the SpeedCalculator output (the locate() columns, smoothed positions, vx, vy).

    10.1 Motion heading¶

    Units. The heading is unit-free, but the reliability threshold is not. - polygons(table, speed_unit=None) computes the speed itself from vx, vy. - Their unit is the speed_unit argument, else table.attrs["speed_unit"] ("mph" or "m/s", as SpeedCalculator writes it), and the threshold is converted to it. - If both are given and differ, or the unit is unknown, or neither is given: ValueError. Some pandas operations drop attrs, so the message says to pass speed_unit.

    Per (track, seg) (base design §8.2): - heading_reliable at speed ≥ heading_min_mph (3); - otherwise hold the last reliable heading, and back-fill before the first; - a segment that is never reliable gets NaN motion heading (handled in §10.2).

    10.2 Footprint orientation¶

    Per (track, seg): 1. Native rows: those whose supplying locator gave an orientation (M3–M7). Every native orientation is folded to an axis for smoothing; the directed value is kept for step 4. 2. Axis smoothing, by the number n of native rows in the segment (as the study's smooth_orientation): - n = 0: no native axis; - n = 1: that axis, unchanged; - n ≥ 2: RTS on the doubled-angle unit vector (rts_smooth, guarded and correctly started, §5.3; orient_q 1.0, orient_sigma 0.1; study ORIENT_Q, ORIENT_SIGMA, both untuned). 3. Reach: the axis is used only within orient_reach_frames (10) of a native row (R10). 4. Direction of an axis, first available: 1. the row's motion heading (reliable, held or back-filled; §10.1). front_source = motion; 2. the segment never moves: the nearest directed native orientation in the segment (M7's ψ, M4's d_front, M3's ψ_ref). front_source = native; 3. the motion heading of the same track's nearest other segment in time. front_source = track; 4. none: the axis is kept with an arbitrary direction. front_source = none, front_known = False. 5. Rows without a native axis in reach use the motion heading, or else step 4.3. If neither exists, orient_deg is NaN and the row has no corners.

    orient_source = native / motion / none. front_known is True unless step 4.4 was used.

    Why fold, and when it matters. - While the vehicle moves, folding directed headings (M3, M4, M7) to axes loses nothing. M7's front rule is travel, so its front already faces the motion. For M4, the front correction already points d_front within 90° of ψ_ref. - A vehicle that never moves keeps its measured axis (step 4.2–4.4), so a parked bus with a passed M7 solve, or a stopped car with good M6 faces, still has an oriented footprint. Only its front may be unknown.

    The directed native value stays in fp_orient_deg, and M4's m4_front_conflict and M7's m7_reversing remain as flags.

    10.3 Size¶

    Per track and segment, in this order: 1. M7 passed solve (the segment's M7 solve has no fail reason): the solve's fitted L and W for every row of that segment (M7 design §9.3). dims_source = m7_measured / m7_partly_prior / m7_prior (M7 design §8.3, with the width-hold rule). 2. Measured classes (m6_measured_size_classes, default (2,)): the median M6 length and width over the track's M6 rows, when there are at least measured_size_min_rows (5; my call). dims_source = m6_measured. 3. Otherwise the class's nominal size (size_ft). dims_source = nominal.

    10.4 Corners and output¶

    corners = rect(centre = smoothed position, orient_deg, length, width), front-left first. Rows supplied by a point_only locator (M1), or without a smoothed position, get NaN corners and dims_source = none.

    Added columns: motion_heading_deg, heading_reliable, orient_deg, orient_source, front_source, front_known, length_ft, width_ft, dims_source, c1x, c1y, c2x, c2y, c3x, c3y, c4x, c4y (corners in world m). With front_known = False, the corner set is correct but which end is "front-left" is arbitrary.

    VehFootPrinter.to_geodataframe(table, crs=None) returns one shapely polygon per row (empty where corners are NaN).

    Low confidence (M7 design §9.6, combine_pet.low_confidence): fp_low_confidence = True on rows of a failed M7 solve that fell back, or on admitted kinematic rows more than lowconf_s (2.0 s) from the nearest supported row. This flag is what a PET step needs.

    11.2 compare()¶

    Runs each method as a single-locator chain on the same grid and reference heading, smooths and polygons each, and returns one long table with a method column.

    Modes. One precedence rule for admit_kinematic in compare():

    fallback admit_kinematic Result
    None (native-only) None or False admission off
    None (native-only) True ValueError: admission contradicts native-only
    set (end-to-end) None config.admit_kinematic (default True)
    set (end-to-end) True / False as given
    • Native-only means measurements of the method's own observations only. A kinematic M7 row has no measurement: fp_source = none, fp_support empty, fp_fail = "M7:no_observation", while m7_support = kinematic stays in the extras.
    • End-to-end (base design §7, without eligibility): admitted rows have fp_source = M7 and fp_support = kinematic; rows the method fails on take the fallback.

    Row contract: every input row, once per method. No row is ever dropped, so the per-method tables pair row by row. - Rows a method does not cover keep their identity, with fp_source = none and fp_fail = "<method>:class_ineligible". Today that is M7 on classes outside m7_classes, such as cars. - The fallback is not applied to class_ineligible rows. An "M7 end-to-end" car would otherwise be pure M2 under the M7 label, and paired M7-vs-M6 comparisons on cars would compare M2 with M6. - Rows outside only_tracks are present with fp_source = none and fp_fail = "excluded".

    It is what a project needs to rebuild the study's comparison: offsets between methods, speed traps, its own metrics.
