I checked each finding against the study's code and the package before changing the design. All four findings are accepted. In each case the study's source code decided the rule. There is still no package code, and the user's decisions Q1–Q5 are unchanged. Section numbers below refer to rev 4.

## Verification performed

- **Finding 1.** In the study's `products._product`, the M7 admission predicate is:
  ```python
  m7_solve_ok & (m7_support == "kinematic") & isfinite(own pose) & isfinite(cov) & ~nat_ok
  ```
  There is no projection term. The display gate `proj_valid` enters only `nat_ok` (`native_valid & gate`). The study's `grid.py` sets `proj_valid = False` on inserted rows ("filled rows carry no Jacobian"). Confirmed: in the study, admission is independent of the box gate. Native M7 rows that fail the gate are neither native nor admitted.
- **Finding 2.** `m7.py` line 1086: `w_held = bool(S.M7_W_HOLD_FT_PER_PX is not None and w_ft_per_px > S.M7_W_HOLD_FT_PER_PX)`, with `M7_W_HOLD_FT_PER_PX = 0.3`. `width_resolution` returns `inf` when no frame's extreme column moves with W. Confirmed: rev 3's "resolves less than 0.3 ft/px" stated the condition backwards, or at best ambiguously.
- **Finding 3.** Confirmed by reading rev 3. §11.2 said admission is off "whatever `admit_kinematic` says" and also that an explicit argument "overrides either default". My previous response, item 9, repeated the second rule.
- **Finding 4.** `smoother._finish()` applies `out[num].round(3)` to every added numeric column. Confirmed: a 1e-6 m test on public output cannot pass, whatever the origin handling.

## Item by item

**1. [P1] Admitted M7 states and the box-projection gate: accepted; the study's rule is adopted.**
- **Three row kinds (§7.10)**, recorded in `fp_row_kind`, with the gate result in `fp_proj_valid`:
  - `box`: an original row with a valid projection;
  - `box_rejected`: an original row whose projection was rejected;
  - `inserted`: a gap frame with no box.
- **The gate governs box observations only.** Every native locator fails a `box_rejected` row with `projection`. Row-scope locators do not run on `inserted` rows (`no_box`).
- **Admission (§7.7)** uses the study's predicate exactly: passed solve, `kinematic` support, finite pose and covariance. It never looks at the box, the Jacobian or the gate. So it applies to `inserted` rows and, as in the study, also **overrides** the rejection on `box_rejected` rows inside a segment.
  - Reason: the M7 pose comes from the camera and the motion model, not from the bbox bottom that the gate judges.
  - `fp_fail` still starts with `projection` on such a row, so the override is visible.
- **The `seg = −1` exclusion is kept:** those rows belong to no segment and no solve, so they are never admitted.
- **No box-derived values on admitted rows.** Position is the M7 pose, covariance is the §7.7 formula, and no Jacobian or `fill_meas_scale` enters.
- **Native M7 rows that fail the gate** are not used by M7 and are not admitted (their support is not `kinematic`), so the next locator in the chain tries them. This matches the study.
- **Test 18** goes through `estimate()`, not the smoother alone, with an inserted gap frame, a `box_rejected` kinematic row, a `box_rejected` native row and a `seg = −1` row. It asserts that the inserted frame's `fp_cov_*` equal the §7.7 covariance exactly, and that the smoothed position differs from the same run with `admit_kinematic=False`.
  - It runs with a stub M7 locator in phase 2 and the real one in phase 5.
  - The smoother-only test 4 stays, because it covers the other half of the path.

**2. [P2] Width-hold direction: accepted.**
- **§7.6** now quotes the study's expression and spells out the rule: `w_ft_per_px` is the width change per pixel (larger is coarser); held when `w_ft_per_px > 0.3`, strictly; exactly 0.3 is not held; `inf` is held; a `None` threshold never holds. The study code is named as authoritative.
- **Test 19** covers 0.29, 0.3, 0.31, `inf` and `None`.

**3. [P2] One precedence rule for admission in `compare()`: accepted, with native-only winning.**
- **The rule (§11.2):** with `fallback=None`, `admit_kinematic` of `None` or `False` means admission off, and `True` raises `ValueError`, because a native-only product with pseudo-measurements is a contradiction. With a fallback, `None` takes the config default (True), and `True` / `False` are used as given.
- **§7.8's single-locator note** now says that a one-locator M7 chain is native-only only with admission off, and points to `compare(fallback=None)`.
- **Test 15** covers all six combinations, including the `fp_source`, `fp_support`, `fp_fail` and `m7_support` values on the kinematic row.
- **This supersedes item 9 of the previous response**, which promised an explicit override in native-only mode.

**4. [P2] The UTM round-trip test against output rounding: accepted; precision is unchanged.**
- **Segmented mode keeps the legacy three-decimal rounding** (§5.2, "Coordinates"). No output precision changes anywhere.
- **Test 3 (§14.2)** has two absolute tolerances (`rtol = 0`) on six-decimal coordinates such as 5200000.123456 m:
  - 1e-6 m for the internal local ↔ world conversion, before rounding;
  - 0.0005 m for the public `<pos>_smooth` columns.

## Not changed

- **Native M7 rows that fail the gate** are not used, following the study, even though their mask observations exist. Those rows are far-field (beyond the 100 ft gate buffer or coarser than 2 ft/px), where M7's own observations are weakest. Changing this would also be a deliberate change from the study, which §15 would have to list. I note it here rather than adopt it.
- The study snapshot (phase 0) and Q6 are as in rev 3. This review does not certify parity or a snapshot, and neither does this response.
