## Item by item

**1. [P1] Invalid projections and the initial grid: accepted.**
- **Segmenting (§5.2).** `TrackSmoother.segment(..., allow_missing=True)` accepts non-finite positions and **keeps** those rows. Jumps and gaps are classified on the finite rows only, and a run of missing rows counts as part of the gap around it:
  - **interior run, gap filled:** the rows stay in the segment, unmeasured, `fill_reason = "no_position"`;
  - **interior run, gap not filled:** the track splits there, and the run gets `seg = −1`;
  - **prefix, suffix, or a track with no finite position:** `seg = −1`, never extrapolated.
- **In `locate()` (§9 step 2):** these rows have `fp_fail = "projection"` and `fp_source = "none"`. No ground point is invented, and every later step returns them with NaN outputs.
- **Tests:** 2 (smooth) and 17 (footprint): one invalid row between valid ones, a long invalid run, an invalid prefix and suffix, a track with no valid projection, every row returned once.

**2. [P1] The reused-grid contract: accepted, by changing the mechanism.**
- **No grid object is passed (§5.2).** `segment()` returns only the structural columns (`track, frame, seg, seg_len, interp, fill_reason, gap_id`), with no positions, so M1 values cannot leak into another method.
- **`smooth(..., segmented=True)`** takes those columns from the input itself:
  - **Validation:** no repeated keys, consecutive frames per segment; `seg_len` is recomputed.
  - **Clashes:** `seg`, `interp` and `fill_reason` are input columns in this mode, so they are no longer clashes; the smoother adds only its position and fallback columns.
  - **Observations:** they come only from this call's positions. `ma`, `sg` and the short-segment fallback interpolate this call's measurements.
  - **Origin:** computed from this call's positions.
  - **Segments without enough measurements:** with 0 measurements, NaN and `fallback = 1`; with 1, that row only.
- **Test 3:** segment on M1, smooth deliberately offset M6 positions with `rts`, `ma`, `sg` and a 1-row segment; a UTM-scale origin; an entirely failed method; the structural columns. The rev 2 test of "same positions, same result" could not detect stale values, as the review says; it is replaced.

**3. [P1] Provenance separated from measurement admission: accepted.**
- **Admission (§5.2):** in segmented mode, a row is measured exactly when it has `seg ≥ 0` and a finite position. `interp` is provenance only and no longer clears observations, so an admitted M7 point on an inserted `interp = 2` frame is used (§7.7).
- **Scaling (§5.1):** supplied covariance columns are **final**; `fill_scale` applies only to σ-based noise.
- **Per support type (§7.9 table):**
  - box rows with `interp = 0`: `R`;
  - box rows with `interp = 1`: `4² R`, the study's `FILL_MEAS_SCALE`;
  - M7 admitted rows: their own covariance, any `interp`, no further scaling;
  - rows without a point: unmeasured.
- **Guard:** `VehFootPrinter` rejects a user smoother not configured with the covariance columns, so the σ path cannot add a second inflation by accident.
- **Tests:** 1, 4 and 10.

**4. [P2] Sparse orientations and missing prefixes: accepted.**
- **`rts_smooth` (§5.3):**
  - fewer than 2 measurements raises `ValueError`, not `IndexError`;
  - the forward pass starts at the first measured row, and earlier rows are extrapolated backward from the smoothed state there. This is exact on constant-velocity data, where today's code is 1.54 m off.
  - Existing callers are unaffected: every segment today starts with a measured row.
- **Orientation (§10.2 step 2):** 0 native rows gives no axis; 1 gives that axis; 2 or more uses RTS. This is the rule of the study's own `smooth_orientation`, which rev 2 dropped by calling `rts_smooth` directly.
- **Tests:** 5 and 12.

**5. [P2] Native axes on vehicles that never move: accepted.** The rev 2 claim that folding "loses nothing" held only for moving vehicles; rev 3 says so (§10.2).
- **Direction of a native axis**, first available (§10.2 step 4):
  1. the motion heading (reliable, held or back-filled);
  2. the nearest directed native orientation in the segment (M7 `ψ`, M4 `d_front`, M3 `ψ_ref`);
  3. the motion heading of the track's nearest other segment;
  4. none: the axis is kept, `front_known = False`.
- **New columns:** `front_source` and `front_known`. Corners are always built when an axis exists; with an unknown front, only the "front-left" label is arbitrary.
- **Test 13:** a stationary car with M6 faces, a stationary M7 bus, and a car that waits and then drives.

**6. [P2] OpenCV, including the existing homography: accepted.**
- **The guarantee is widened, not narrowed** (§2, §13). Without OpenCV, these must work:
  - `import tssa`;
  - `load_json` / `load_matrix` of both homography classes, and projection in both directions;
  - the camera fit;
  - M1–M4 and M6.
- **Code changes:**
  - `homography.py` imports `cv2` only where it fits;
  - projection becomes a numpy homogeneous product, held to 1e-9 against today's results and the unchanged `test_homography`;
  - the constructor default becomes `method=None`, meaning RANSAC.
- **Camera (§8):** it drops OpenCV too: `scipy.spatial.transform.Rotation` replaces `cv2.Rodrigues`, and a numpy DLT replaces the initial `cv2.findHomography(…, 0)`. Parity is checked against the run report's camera (§14.3).
- **Still needs OpenCV:** fitting a new homography, and M5 and M7, which rasterise masks.
- **Test 8** blocks `cv2`, `torch` and `ultralytics` and exercises the public loading path. The build order moves this into phase 1.

**7. [P2] Image size and distortion adapter: accepted.**
- **New `tssa.transform.ground.GroundModel.wrap(homography, image_size=None)` (§4.2):**
  - identity `undistort` / `distort` for ordinary homographies;
  - `world_to_undistorted` through the inner homography where there is one, avoiding the iterative `distort()` round trip;
  - a half-implemented distortion pair is rejected.
- **Image size:** taken from the explicit argument, else from the homography's attribute. A conflict, or no source at all, raises at construction.
- **Camera space (§8):** it fits and checks consistency in undistorted pixels, with the principal-point prior toward the centre of `image_size`.
- **Tests 6 and 7** cover an ordinary and a distorted homography.

**8. [P2] Speed units: accepted.**
- `polygons(table, speed_unit=None)` computes speed from `vx, vy` in the unit given by the argument, else by `attrs["speed_unit"]`, and converts the 3 mph threshold to that unit (§10.1).
- A missing, unknown or conflicting unit raises with a message about lost `attrs`. `estimate()` passes the unit explicitly.
- **Test 14:** metric and imperial calculators give identical reliability and orientation.

**9. [P2] Native-only comparison and M7 pseudo-measurements: accepted.**
- **Native-only (`fallback=None`)** turns admission off automatically (§11.2): a `kinematic` row is unmeasured, `fp_fail = "M7:no_observation"`, and `m7_support = kinematic` is kept in the extras.
- **End-to-end** follows `admit_kinematic`.
- **Override:** an explicit `compare(admit_kinematic=…)` overrides either mode.
- **Test 15.**

**10. [P2] Comparison row count: accepted; the row guarantee wins.**
- Every input row appears once per method (§11.2). Rows a method does not cover get `fp_fail = "<method>:class_ineligible"`; rows outside `only_tracks` get `excluded`.
- **The fallback is not applied to `class_ineligible` rows.** Otherwise "M7 end-to-end" cars would be pure M2 under the M7 label, and paired M7-vs-M6 comparisons on cars would compare M2 with M6.
- **Test 15:** a mixed car/bus input and `only_tracks`.

**11. [P2] Detector row selection: accepted.**
- **`detect.run` is configuration-independent (§6.4).**
  - `tracks` is always the whole-frame matching context;
  - `rows` selects only output and cached rows;
  - the default is every row of `tracks`.
- **`VehFootPrinter.required_rows(tracks)`** returns per-table rows from the printer's chains: car rows appear under `masks` when a custom car chain has M5. The public example shows both uses.
- **Cache key:** it hashes the full track table, because matching depends on every box of a frame.
- **Test 19** uses a fake detector, so it needs no model.

## Source handoff

Accepted. Per-file hashes alone cannot show that all ported files come from one validated state. §17 adds a **phase 0**: a read-only archive of the study's code, documents and settings, and a manifest committed in `tssa` (`docs/study-snapshot-<date>.json`). The manifest holds:

- the full settings;
- the cache-table schemas with one example row each;
- `pip freeze` of the study environment and the checkpoint hashes;

Code is ported only from the archive, and each ported file's docstring cites the manifest.
